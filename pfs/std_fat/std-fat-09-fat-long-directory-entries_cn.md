## FAT 长文件名目录项

向 FAT 文件系统添加长目录项时, 关键要求是在现有设计上:

1. **对早期 MS-DOS 版本基本透明.** 主要目标是旧版 MS-DOS/Windows 上的现有 MS-DOS API 不易 "发现" 长目录项. 唯一能 "发现" 长目录项的 MS-DOS API 是 FCB 查找 API, 且须使用完整通配符匹配模式 (即 `*.*`) 与完整属性匹配位 (即匹配属性为 FFh). 在 Windows 95 之后版本的 MS-DOS/Windows 上, 没有任何 MS-DOS API 会意外 "发现" 单个长目录项.

2. **在介质上与关联的短目录项物理位置邻近.** 长目录项与关联短目录项紧邻, 对文件系统性能影响可忽略.

3. **若被磁盘维护工具检测到, 不危及现有文件数据完整性.** 磁盘维护工具通常不使用 MS-DOS API 访问介质上文件系统特定数据结构, 而是读取磁盘物理或逻辑扇区并自行判断目录项内容. 基于工具采用的启发式, 可能采取各种步骤 "修复" 其认为 "损坏" 的文件系统特定数据结构. 长目录项的添加方式确保: 若含长目录项的磁盘在旧版 MS-DOS/Windows 上被 Windows 95 之前兼容的磁盘工具 "修复", 不会导致文件数据丢失.

为满足局部性 (locality-of-access) 与透明性目标, 长目录项定义为具有特殊属性的短目录项. 如前所述, 长目录项即为属性字段取下列值的普通目录项:

```
ATTR_LONG_NAME    ATTR_READ_ONLY |
                  ATTR_HIDDEN |
                  ATTR_SYSTEM |
                  ATTR_VOLUME_ID
```

判定条目是否为长名子组件的掩码也应定义:

```
ATTR_LONG_NAME_MASK    ATTR_READ_ONLY |
                       ATTR_HIDDEN |
                       ATTR_SYSTEM |
                       ATTR_VOLUME_ID |
                       ATTR_DIRECTORY |
                       ATTR_ARCHIVE
```

遇到此类目录项时, 文件系统特殊处理: 将其视为与单个短目录项关联的一组目录项的一部分. 每个长目录项结构如下:

### FAT 长目录项结构

| **名称** | **偏移 (字节)** | **大小 (字节)** | **说明** |
| --- | --- | --- | --- |
| LDIR_Ord | 0 | 1 | 本项在长目录项序列中的序号, 该序列与长目录项集末尾的短目录项关联. 若与 0x40 (`LAST_LONG_ENTRY`) 按位或, 表示本项为该长目录项集中的最后一项. 所有有效长目录项集必须以带此掩码的项开头. |
| LDIR_Name1 | 1 | 10 | 本目录项中长名子组件的第 1–5 个字符 (UTF-16). |
| LDIR_Attr | 11 | 1 | 属性 — 必须为 `ATTR_LONG_NAME`. |
| LDIR_Type | 12 | 1 | 若为 0, 表示作为长名子组件的目录项. **注**: 其他值保留供将来扩展; 非零表示其他 dirent 类型. |
| LDIR_Chksum | 13 | 1 | 长目录项集末尾短目录项中名称的校验和. |
| LDIR_Name2 | 14 | 12 | 本目录项中长名子组件的第 6–11 个字符. |
| LDIR_FstClusLO | 26 | 2 | 必须为 **ZERO** (0). 这是 FAT "first cluster" 设计的遗留, 为与现有磁盘工具兼容须为零; 在长目录项上下文中无意义. |
| LDIR_Name3 | 28 | 4 | 本目录项中长名子组件的第 12–13 个字符. |

### 短目录项与长目录项的组织与关联

一组长目录项始终与紧随其后的短目录项关联. 长目录项与短目录项配对的原因: 仅短目录项对旧版 MS-DOS/Windows 可见. 若无短目录项伴随, 长目录项在旧版系统上完全不可见. 长目录项 **不得** 单独合法存在. 若发现长目录项未与有效短目录项配对, 称为 **orphans** (孤儿项).

长目录项 **始终紧接** 并 **物理连续** 于关联的短目录项之前. 文件系统还进行其他检查以确保长目录项集确实与短目录项关联.

### 长目录项序列

| 条目 | LDIR_Ord 值 |
| --- | --- |
| 第 N 个长目录项 | N |
| 最后一个长目录项 | `LAST_LONG_ENTRY (0x40) \| N` |
| 第 1 个长目录项 | 1 |
| 与前面长目录项关联的短目录项 | (不适用) |

首先, 长目录项集中每个成员有唯一编号, 最后一个成员与标志按位或表示其为集的最后成员. 使用 `LDIR_Ord` 判定. 集的第一个成员 `LDIR_Ord` 为 1. 第 n 个长成员值为 `(n OR LAST_LONG_ENTRY)`. 注意 `LDIR_Ord` 不能为 0xE5 或 0x00 (文件系统一直用这两个值表示 "free" 目录项或簇中 "last" 目录项). `LDIR_Ord` 取值范围不在此两值上. 值必须从 1 到 `(n OR LAST_LONG_ENTRY)`. 否则长目录项 "damaged" (损坏), 文件系统将其视为孤儿.

其次, 在创建短目录项与长目录项时, 对短目录项中名称 (全部 11 字符) 计算 8 位校验和. 校验和写入每个长目录项. 若长目录项集中任一校验和与短目录项名称计算值不一致, 长目录项视为孤儿. 这可能发生在含长短目录项的磁盘被带到旧版 MS-DOS/Windows 且仅重命名了带长目录项的文件或目录的短名时.

校验和算法 (C 实现):

```c
//-----------------------------------------------------------------------------
//  ChkSum()
//  对无符号字节数组计算 8 位无符号校验和.
//  数组须为 11 字节, 假定含 MS-DOS 目录项格式存储的名称.
//  参数:  pFcbName    指向假定 11 字节长的无符号字节数组.
//  返回:  Sum         指向 pFcbName 的数组的 8 位无符号校验和.
//------------------------------------------------------------------------------
unsigned char ChkSum(unsigned char *pFcbName)
{
    short FcbNameLen;
    unsigned char Sum;

    Sum = 0;
    for (FcbNameLen = 11; FcbNameLen != 0; FcbNameLen--)
    {
        // NOTE: 无符号字节右旋
        Sum = ((Sum & 1) ? 0x80 : 0) + (Sum >> 1) + *pFcbName++;
    }
    return (Sum);
}
```

因此短目录项承载: 最后访问日期、创建时间、创建日期、首簇、大小等字段, 以及旧版 MS-DOS/Windows 可见的名称. 长目录项可含新信息, 无需复制短目录项已有信息. 长目录项 principally 含文件长名. 与长目录项集关联的短目录项中的名称称为文件的 **alias name** (别名), 或简称 **alias**.

### 长名在长目录项中的存储

长名可含超过单个长目录项容量的字符, 此时名称存储在多个长目录项中. 无论如何, 长目录项内各名称字段互不重叠.

名称以 NUL 终止, 并以 0xFFFF 字符填充, 以便检测磁盘工具误改长名字段. 若名称恰好占 n 个长目录项 (即 13 的整数倍字符), 则 **不** NUL 终止, **不** 以 0xFFFF 填充.
